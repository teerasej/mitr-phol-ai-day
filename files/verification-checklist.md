# Verification Checklist

ใช้รายการนี้ทุกครั้งก่อนนำคำตอบจาก Copilot ไปสื่อสาร ตัดสินใจ หรือใช้เป็น input ของงานถัดไป เครื่องหมายถูกไม่ได้แปลว่า AI ถูกเสมอ แต่แปลว่า BA ได้ตรวจจุดสำคัญแล้ว

## Source

- [ ] ระบุ source ที่อนุญาตให้ใช้ครบ
- [ ] แยก source ที่ตรวจสอบแล้วออกจาก interview note หรือ draft ที่ยังไม่ sign off
- [ ] คำตอบอ้างถึง source ที่มีอยู่จริงและไม่สร้างชื่อเอกสารเพิ่ม
- [ ] ถ้าใช้ web source ได้เปิดหน้า source และตรวจเนื้อหาจริง ไม่ดูเฉพาะข้อความสรุปหรือ citation title

## Fact, assumption, gap และ open question

- [ ] Fact ทุกข้อย้อนกลับไปหา source ได้
- [ ] Interpretation หรือ assumption ถูกติดป้ายชัดเจน
- [ ] Gap ไม่ถูกเติมด้วยการคาดเดา
- [ ] Open question ระบุ stakeholder ที่ควรถามเมื่อรู้ได้จากบริบท
- [ ] Unsupported claim ถูกลบหรือเปลี่ยนเป็นสิ่งที่ต้องตรวจสอบ

## Citation และ number

- [ ] Citation สนับสนุนประโยคที่อ้างจริง
- [ ] ตัวเลข จำนวน วันที่ และหน่วยตรงกับ source
- [ ] ผลรวม ค่าเฉลี่ย หรือการเปรียบเทียบถูกคำนวณซ้ำอย่างน้อยหนึ่งครั้ง
- [ ] ไม่เปลี่ยนคำว่า “เสนอ”, “คาดว่า” หรือ “น่าจะ” ให้กลายเป็นข้ออนุมัติแล้ว

## Requirement quality

- [ ] Requirement ระบุผู้ใช้หรือบทบาทและผลลัพธ์ที่ต้องการ
- [ ] แยก overlap, conflict, dependency และ missing information
- [ ] คำที่กำกวม เช่น `urgent`, `high impact`, `เร็ว` หรือ `ง่าย` มีคำถามสำหรับนิยาม
- [ ] Requirement ที่ขัดแย้งกันยังไม่ถูกเลือกแทน stakeholder

## Communication and action

- [ ] Output เหมาะกับผู้รับและช่องทางสื่อสาร
- [ ] Action มี owner และ due date หรือระบุชัดว่ายังไม่ยืนยัน
- [ ] Dependency และ unresolved item ไม่ถูกซ่อน
- [ ] Tone เป็นกลาง กระชับ และไม่กล่าวเกินหลักฐาน
- [ ] ผู้รับสามารถแยกได้ว่าอะไรคือ decision, proposal, question และ next step

## Final decision

- [ ] `พร้อมใช้` — ตรวจหลักฐานและข้อจำกัดครบ
- [ ] `ใช้ได้เมื่อแก้ไข` — ระบุจุดที่ต้องแก้ก่อนส่ง
- [ ] `ยังไม่ควรใช้` — ต้องขอข้อมูลหรือการยืนยันเพิ่มเติม
